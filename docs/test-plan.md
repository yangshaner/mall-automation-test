# 测试方案

## 1. 测试范围

| 层面 | 覆盖 | 不覆盖 |
|---|---|---|
| 接口 | 后台品牌/分类/商品/订单/优惠券/限时购；会员登录/购物车/下单/地址/收藏；鉴权安全 | 第三方支付真实对接、短信邮件外发 |
| UI | 会员端 H5 购买主流程、后台登录与列表 | 多浏览器矩阵（仅 Chromium） |
| 性能 | 浏览、加购、交易的混合流量，阶梯至 50 并发 | 容量上限摸高、2 小时以上稳定性 |

## 2. 分层策略

| 层次 | 职责 |
|---|---|
| 接口层 | 承载绝大部分业务规则、鉴权、数据一致性校验，执行快、易定位 |
| UI 层 | 只验证用户能否走通，并在操作后调用接口复核数据 |
| 性能层 | 复用接口层的请求构造与断言口径，做混合流量与阶梯压测 |

同一业务点不在两层重复堆用例；UI 层不重复断言界面文案，而是验证结果是否真正落库。

## 3. 用例设计方法

| 方法 | 应用示例 |
|---|---|
| 等价类 / 边界值 | 加购数量：1、库存上限、0、负数、库存 +1 |
| 场景法 | 正常下单；无默认地址；无任何地址；流程中 Token 失效 |
| 状态迁移 | 订单 待付款 → 待发货 → 待收货 → 已完成 / 已关闭，含非法迁移 |
| 安全 / 异常 | 越权访问、未认证访问、空或畸形参数、使用他人 cartId / addressId 下单 |

异常场景的断言标准是"服务端拒绝且不产生副作用"，而不只是返回非 200。

## 4. 断言与数据

| 层次 | 断言内容 |
|---|---|
| HTTP | 状态码、响应时间上限 |
| 业务 | `code == 200`、分页结构、关键字段非空 |
| 数据 | MySQL / Redis 校验落库结果 |
| UI | 元素可见可点击 + 接口复核 |

测试数据按角色维护账号池，动态数据用 Faker 生成，依赖的历史数据优先走接口获取、取不到再查库，用例结束后清理自建数据。

## 5. 准入准出

**准入**：服务可访问、核心接口可用、测试数据就绪、配置校验通过。

**准出**：

| 项 | 标准 |
|---|---|
| 接口用例 | 通过率 ≥ 95%，失败项均有缺陷记录或明确跳过原因 |
| UI 用例 | 核心链路全部通过 |
| 性能 | 目标并发下错误率 < 1%，P95 在约定阈值内 |
| 遗留缺陷 | 无阻塞级问题，严重级有修复计划 |

被测系统自身缺陷不做断言放宽，跳过用例必须写明原因。
