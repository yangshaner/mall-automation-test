# 性能压测报告

## 1. 测试目标

对 mall 会员端（API 8085）做混合流量压测，观察不同并发档位下的响应时间、错误率，以及 MySQL / Redis 资源水位，定位瓶颈组件。

## 2. 测试环境

| 项 | 值                                     |
|---|---------------------------------------|
| 被测服务 | mall-admin / mall-portal（Spring Boot） |
| 数据库 / 缓存 | MySQL 5.7 / Redis 7.0                 |
| 压测机 | Windows 11、Python 3.13、Locust 2.46    |
| 目标机 | 单台 8 GB 虚拟机，MySQL + Redis + 后端同机部署    |

## 3. 流量模型

按真实电商访问比例模拟三类用户：

| 用户类型 | 权重 | 行为链路 |
|---|---:|---|
| 浏览 | 70% | 品牌商品列表 → 品牌推荐 → 品牌详情（免登录） |
| 加购 | 15% | 登录 → 查商品 → 加购 → 查购物车 |
| 交易 | 15% | 登录 → 加购 → 查购物车 → 取地址 → 下单 → 查订单 |

思考时间：浏览 1~3 秒，交易 2~5 秒。

## 4. 阶梯负载

5 → 10 → 20 → 35 → 50 并发共 5 档，总时长 75 分钟，逐档递增并记录时间线，便于把每个请求归到对应档位。

| 档位 | 并发 | 时长 | 目的 |
|---|---:|---:|---|
| S1 | 5 | 5 min | 冒烟与数据预热 |
| S2 | 10 | 10 min | 轻度真实流量 |
| S3 | 20 | 15 min | 常规业务高峰 |
| S4 | 35 | 20 min | 峰值预警线 |
| S5 | 50 | 25 min | 极限探测 |

## 5. 运行方式

```bash
# 冒烟（恒定负载）
locust -f performance/locustfile.py --headless -u 10 -r 2 -t 2m --host http://127.0.0.1:8085

# 5 档阶梯
locust -f performance/locustfile.py \
  --shape performance.orchestration.shape.InstrumentStepShape \
  --headless -u 1 -r 1 --host http://127.0.0.1:8085

# 压测结束后重新生成对齐报告
python -m performance.analysis.align
```

压测前需将 `performance/data/users.csv`、`products.csv` 替换为真实环境数据，并确保账号数不少于最高并发档位。

## 6. 结果

一次 5 → 10 → 20 三档、20 分钟的探测结果（`aligned_report.csv`）：

| 档位 | 并发 | 接口 | 请求数 | 错误率 | 平均耗时 | P95 |
|---|---:|---|---:|---:|---:|---:|
| S1 | 5 | /brand/list | 320 | 0.3% | 42 ms | 88 ms |
| S1 | 5 | /brand/recommend | 180 | 0.0% | 51 ms | 110 ms |
| S2 | 10 | /brand/list | 720 | 0.8% | 65 ms | 180 ms |
| S2 | 10 | /cart/add | 40 | 1.2% | 95 ms | 210 ms |
| S3 | 20 | /brand/list | 1680 | 2.1% | 142 ms | 420 ms |

| 档位 | MySQL QPS | MySQL 连接数 | Redis 客户端数 | Redis 内存 |
|---|---:|---:|---:|---:|
| S1 | 1,200 | 8 | 15 | 45 MB |
| S2 | 2,800 | 14 | 22 | 62 MB |
| S3 | 6,100 | 28 | 38 | 95 MB |

## 7. 结论

- 20 并发时 `/brand/list` P95 从 88 ms 升至 420 ms，同期 MySQL QPS 与连接数同步翻倍，瓶颈在数据库连接池
- Redis 内存增长平缓，未达到瓶颈
- 主报告成功率稳定在 97.9%；已知订单链路鉴权问题单独标记为探测项，不计入成功率

建议：品牌列表接口单独优化索引，并按最高并发档位调整数据库连接池。
